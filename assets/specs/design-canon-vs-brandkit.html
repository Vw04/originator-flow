02 · New · Working Agreement

Behavioral contract for Claude Code (kit's new top section)

The 2026-05-19 handoff opens with a "Working Agreement" — a behavioral contract Claude Code is expected to follow when working on Homium. This is a meta-pattern (how the system is maintained), not a visual one, but it materially affects how new components get added. Worth surfacing.

The default — always

  • Describe before tweaking. Preview every change before it lands. One-line for small edits; brief plan with file paths for larger.
  • Reuse over invent. Use existing tokens, components, and patterns. Never invent a new color, spacing unit, pill shape, button variant, or layout without approval.
  • Surface options. When a task could go several ways, present 1–3 approaches with trade-offs.
  • Files are the source of truth. Read current state before editing. Don't work from memory.

Stop and ask before…

  • Adding a new library component (Modal variant, card type, button modifier, chart type, form-field variant)
  • Adding or modifying design tokens — colors, spacing, type, radii, shadows
  • Introducing a new pattern — table column type, sticky-bottom variant, dirty-state mechanism, keyboard shortcut
  • Breaking changes — renaming a class, retiring a component, changing a CSS var's meaning
  • Out-of-scope edits — flag consistency drift as separate follow-up; don't fix it silently in the same PR

Safe without asking

  • Use any existing component, token, layout, or pattern exactly as documented
  • Apply explicit instructions exactly as given ("change the button to outlined" — just do it)
  • Restate your plan before editing — that's confirming intent, not asking permission

When something isn't covered

  • Identify what pattern they're asking for (your interpretation)
  • List what already exists nearby that might solve it
  • Present 2–3 options if a new pattern is needed, with trade-offs
  • Give your recommendation — but ask before implementing

Implication for our work: the contract makes "tokens-first, components from the library" the default. The Phase 4 PR that resolves these audit items should align — surface the per-row decisions as options the user picks before implementation, and update CLAUDE.md / canon doc in the same pass where new patterns land. This matches our existing workflow well.

03 · New patterns since the prior audit

2026-05-19 highlights — patterns not in prior audit

Six patterns the dev team locked in since their May 5 doc. None conflict with what we shipped; all are additive. Listed roughly in order of platform impact.

Heading font: Source Serif 4 (not Georgia)

Adobe's open-source modern serif, served from Google Fonts. Ships native lining figures, so the old HeadingNumFix @font-face workaround is gone. Token: --h-font-heading: 'Source Serif 4', Georgia, 'Times New Roman', serif. Weight always 400, never bold. Now used for page titles, section titles, KPI numbers (36px display).

Recommendation · Negotiate Same conversation as the prior audit's IvyPresto vs Georgia call — but the dev team's serif is now a more deliberate choice. They moved off Georgia for a specific OpenType / lining-figure reason. We hold the IvyPresto Display license; do we want to keep it, or align to Source Serif 4 for an exact match?

Form-page navigation locked in

Sticky BackToMain link at top (top: var(--h-top-nav-height)) + sticky-bottom Save-only bar + dirty-form modal covering all four exit paths (top Back, sidebar nav, top-nav, browser back/reload). Verified in live prototype: .SaveBar { position: fixed; ... justify-content: flex-end; }.

Recommendation · Adopt kit The Save-only pattern was already in the prior audit at "critical" component severity — confirmed canonical in the new handoff. Remove the Cancel button from .inst-footer-bar in our branches.js; rely on sticky-top BackToMain as the cancel route.

Modal primitive (single shared library)

One shared <div class="Modal" id="..."> at end of <body>. Wired per call: openModal(id, { onConfirm, onDismiss }). closeModal() cleans up + restores focus. Tab is trapped while open. Used for the Discard-changes confirm, but generic — reuse for any destructive flow (delete entity, revoke access).

Recommendation · Adopt kit When we wire the dirty-form modal, build it on this primitive. One canonical confirm flow, not per-page reinvention.

PermissionsMatrix — dot vocabulary

Access-level is communicated by a leading dot inside the dropdown, not a fill. Hollow ring = No access · filled gray = View only · filled blue = Can edit · filled green = Full access. Same vocabulary mirrored in the HelpTooltip header legend, one-to-one. Replaces the old filled-blue selected-state appearance.

Recommendation · Adopt kit When we touch platform-rbac.js, align the matrix to the dot vocabulary. Use --success / --info / --text-muted tokens, plus a hollow-ring variant.

Setup section nav simplified

The duplicate in-page left SideNav was removed from Setup pages. The top NavBar dropdown (Setup → Companies / Branches / Users) is now the single nav source. The .DetailPage flex shell stays but only the content child renders.

Recommendation · Adopt kit Conditional — depends on the nav architecture call. If we go top-nav, this falls out automatically. If we stay left rail, we still keep the principle: don't double-nav with a sub-sidebar when the main nav already shows the section.

Role pill convention

All role pills use full names, never abbreviations. Sentence case, no text-transform: uppercase. "Loan Officer" not "LO" or "LOAN OFFICER". Visually identical across all roles — only the label differentiates.

Recommendation · Adopt kit Audit our role chips in branches.js, users.js, companies.js. Replace any abbreviations or uppercase styling.

Type-scale rule (page H1 outranks card section title)

Page-level H1 = 28px (.PageHeader__title or .SectionTitle--page modifier). Card section title = 20px (.SectionTitle). Detail-entity title = 28px Source Serif 4 (.DetailHeaderCard__title). Rule: never use 20px for a page-level title.

Recommendation · Adopt kit Our .page-title is already 28px (consistent). The new bit is the explicit 20px section-title size for serif headings inside cards. Update our .inst-card-title from Inter 15px Semibold to Source Serif 4 20px Regular if we adopt the font swap.

Tab spacing rule

16px below the tab strip — platform-wide. Previously the tab strip + content gap stacked to 40px in some places. Fixed.

Recommendation · Adopt kit Audit our .section-tabs margin-bottom in the detail-view tabs (branches.js).

Patterns the kit declares canonical that we have no analog for

Same list as the prior audit, retained for completeness. All additive, not in conflict. Recommendations match the prior audit unless re-validated below.

Data viz palette

Sequential teal ramp, categorical 6-color, diverging red→green (only place red/green appear in charts). Opacity stepping --step-1…5 for single-variable bars. Multi-series order: #00334A → #1A6E8E → #A3C5D4.

Adopt when first chart is built.

Chart tooltip pattern

White bg, 1px stone border on all sides, 3px green-500 top accent (direction-independent, never left/right). Two-line content: Inter 11px label + Source Serif 4 18px value.

Adopt with first chart.

Dim-siblings hover

On chart bar hover: container gets .is-hovering, bar gets .is-hovered. All bars dim to 0.40, hovered bar 0.85. Never filter: brightness().

Adopt with first chart.

Tabler Icons (1.5px stroke)

Standard icon library. 20px standalone, 16px inside components. Never mix libraries. In HTML prototypes, use inline SVG matching Tabler path data.

Adopt immediately. Audit existing inline SVGs.
