00 · Adopted 2026-05-26

Working Agreement

Behavioral contract Claude Code (and any contributor) follows when working on this codebase. Adopted verbatim from the 2026-05-19 brand-kit handoff.

1 · Describe before tweaking

State the change and affected files before editing. Don't surprise the reviewer.

2 · Reuse over invent

Never introduce a new color, spacing unit, component variant, or pattern without approval. Reach for existing tokens first.

3 · Surface options

When ambiguous, present 1–3 approaches with trade-offs. Let the user choose; don't pick silently.

4 · Files are source of truth

Read the file before editing. Don't work from memory of "what it should say."

04a · Adopted 2026-05-26

Modal primitive — AppModal

Single shared modal primitive at js/modal.js. All confirm/destructive flows (discard changes, delete entity, deactivate user, revoke access) MUST reuse it. No per-page modal reinvention. Esc dismisses, Tab is trapped within the panel, focus restores to the trigger on close.

API

AppModal.open({
  title:    'Deactivate Marcus Webb?',
  subtitle: 'This revokes platform access immediately',
  body:     '<p>...</p>',
  danger:   true,
  size:     'lg',                          // 'sm' | '' (default ~520px) | 'lg' | 'xl'
  actions:  [['Cancel',     'X.close()'],
             ['Deactivate', 'X.confirm()']],
});
AppModal.close();

Visual

  • Radius 12px on the panel
  • Title: IvyPresto 300, 20px
  • Last action button is primary (or danger if danger: true); preceding buttons are secondary
  • Overlay: rgba(10,20,15,0.45) + 2px backdrop blur

Migrated callers

  • app.js · OriginationsView "New Application"
  • platform-rbac.js · Change user type, Deactivate user

Welcome hero overlay (welcome.js) keeps its bespoke layout — it's a marketing splash, not a confirm/destructive flow, so the primitive's scope doesn't apply.

PermissionsMatrix — binary on/off OR explicit "View"/"Edit" text

Dot vocabulary (hollow ring / filled gray / filled blue / filled green) NOT adopted. Permissions express access in one of two ways: (A) binary toggle (filled blue selected · no fill off), or (B) explicit text labels ("View" / "Edit"). Do not introduce intermediate dot states. No platform-rbac.js code changes required this pass.

Action bars

Sticky top "Back to X" + sticky bottom Save/Submit/Next. Together they frame editable pages and keep primary actions reachable without scrolling.

Unsaved changes

Scope rule

The sticky-bottom action bar appears only on form/wizard pages and the edit sub-routes of hybrid pages. List-only views (rosters, dashboards) do not get the bar — there's nothing to save. See the rollout table below.

Dirty state

On entering edit mode, the body class is-dirty is unset and the indicator reads "No changes" in muted gray. The first input event in the form bubbles up to a delegated handler that adds is-dirty, flipping the dot + label to brick-red ("Unsaved changes"). Save and Cancel both clear the flag.

Save/Cancel — Four patterns (2026-05-27 canon)

Per v2 canon, four save/cancel patterns exist. Each maps to a distinct user mental model. Do not conflate them. Pattern D is implemented in this codebase; A/B/C are documented for when their views are built.

A · Wizard / origination flow

Bottom sticky bar: ← See All Applications · AutoSave indicator · Save & Exit · Previous · Continue →. No Cancel. AutoSave removes the discard choice. Dirty-form modal does NOT fire. Not yet implemented — used by wizard views when AutoSave is wired.

B · Inline entity edit (header card)

Save / Discard live INSIDE the detail header card. "Discard" is hidden until dirty; appears as Btn--ghost. "Save changes" disabled until dirty. Explicit Discard click = no modal (intent is clear). Not yet implemented in this codebase.

C · Tab-level commit

Single "Save changes" button, bottom-right. No Cancel. Switching tabs / clicking rail / browser-back while dirty fires the dirty-form modal. Permissions tab is the prototypical case; not yet implemented.

D · Full-page edit form ✓ Implemented

Cancel + Save changes in bottom bar. Cancel = explicit intent → no modal. Unintentional nav-away (rail, tab, BackToMain, browser back) fires the dirty-form modal via AppModal.confirmDiscard. Wired through js/form-state.js on: branches.js, profile.js, origination-companies.js, branch-create.js, oc-create.js.
